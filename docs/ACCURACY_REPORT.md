# تقرير الدقة والمخاطر

## تعريف الخطأ

```
PercentageError = abs(PredictedPrice - ActualCompletedPrice) ÷ ActualCompletedPrice × 100
```

## معايير القبول المستهدفة

| المعيار | الهدف |
|---------|--------|
| نسبة الأخطاء &lt; 10% | ≥ 90% من العينات |
| MAPE | &lt; 2% |
| Median Error | &lt; 1.5% |
| P95 Error | &lt; 5% |
| حجم العينة | ≥ 300 صفقة مكتملة حقيقية |
| تجار مستقلون | ≥ 10 |
| اتجاهات | شراء وبيع |
| فئات | 100k / 500k / 1m+ |
| مسارات | Bankak و MTN MoMo |
| زمني | walk-forward بلا تسريب مستقبل |

## الحالة الحالية (صادق)

**لا يُدَّعى تحقيق معايير الدقة.** ملف `data/calibration/real-completed-trades.json` فارغ من صفقات حقيقية. البيانات التجريبية في البذرة مُعلَّمة `demo_seed` / `SYNTHETIC_TEST` ولا تدخل وزن المؤشر الحي كإثبات.

عينة المعايرة 2026-07-27 مؤرخة للتوضيح فقط (نظري 25,587.78 مقابل ميداني 25,200، فرق 1.54%).

شغّل `pnpm accuracy` لتوليد `docs/ACCURACY_REPORT.json`.

## البيانات الناقصة وكيفية جمعها بأمان

1. ثبّت `apps/trader-connector` على جهاز التاجر.
2. مفتاح Binance بصلاحية **قراءة** تاريخ C2C فقط — يبقى محلياً.
3. الموصل يصفّي COMPLETED ويزيل PII ويرفع إلى `/v1/ingest/trades`.
4. كرّر عبر ≥10 تجار مستقلين واتجاهين وفئات المبالغ.
5. أعد `pnpm accuracy` بعد توفر ≥300 صفقة.

## مخاطر

- سيولة أحادية شائعة على Bankak لمبالغ كبيرة → يجب إظهار «لا يوجد سعر تنفيذي» لا اختراع رقم
- تلاعب إعلانات / تداول ذاتي → تنقية + سقف وزن
- تعطل مصدر غير رسمي → لا يوقف المؤشر
- الأسعار الرسمية قد تبتعد عن السوق الموازي → للكشف لا للفرض
