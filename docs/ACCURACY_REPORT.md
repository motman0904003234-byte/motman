# تقرير الدقة والمخاطر — صادق

تاريخ القطع: 2026-07-27

## ما تحقق برمجيًا

- محرك تسعير مساري مع فصل EXECUTABLE / ESTIMATED_NON_EXECUTABLE / NO_EXECUTABLE_LIQUIDITY
- VWAP على عمق العروض للمبلغ الكامل
- Weighted Median + سقف وزن التاجر 10%
- Provider Adapters مستقلة
- API + PWA RTL + بوت Telegram + موصل محلي
- اختبارات وحدات/تكامل للمسارات الحرجة، السيولة الأحادية، الشواذ، ورفض الحمولات الشبيهة بالأسرار

نتائج الاختبارات المحلية عند الإصدار:

- `pytest`: جميع اختبارات المستودع الحالية ناجحة على بيانات اصطناعية/محلية

## ما لم يتحقق بعد (لا تُختلق نتائج)

| المعيار | الحالة |
|---|---|
| ≥300 صفقة مكتملة **حقيقية** | غير متاح في هذه البيئة |
| ≥10 تجار مستقلين حقيقيين | غير متاح |
| MAPE < 2% على بيانات حية | **لا يُدعى** |
| Median Error < 1.5% حية | **لا يُدعى** |
| P95 < 5% حية | **لا يُدعى** |
| Binance C2C live history | يعتمد على مفاتيح قراءة فقط لدى التجار |
| تغذية رسمية حية CBOS/BNR | موصل موجود؛ يحتاج مصادر/موافقة تشغيلية |

`claim_live_accuracy = false` ما دامت العينات اصطناعية أو أقل من العتبات.

## كيف تُجمع البيانات الخاصة بأمان

1. يشغّل التاجر `connector/local_c2c_connector.py` محليًا.
2. يضع `BINANCE_API_KEY` / `BINANCE_API_SECRET` في بيئة جهازه فقط (صلاحية قراءة).
3. الموصل يرسل فقط الحقول المسموحة إلى `/api/v1/traders/completed`.
4. تُقيَّم الدقة عبر `/api/v1/accuracy/evaluate` بتقسيم زمني walk-forward دون تسريب المستقبل.

## مخاطر معروفة

- إعلانات P2P قابلة للتلاعب والكميات الوهمية
- سيولة Bankak قد تكون أحادية الاتجاه لشرائح كبيرة
- الفرق بين النظري والميداني (عينة 1.54%) يظهر تكلفة الوساطة والمخاطر
- الاعتماد على واجهة غير رسمية ممنوع كمصدر وحيد؛ الموصل الحي اختياري ومفصول
- المخاطر التنظيمية لتطبيقات الصرف عبر الحدود عالية إذا أُضيف التنفيذ لاحقًا

## الخلاصة

النظام **قابل للتشغيل كمنصة بيانات/تنبيهات** مع منهجية شفافة.
**لا يثبت هذا التقرير دقة سوق حية 90%+/MAPE<2%** حتى تُستورد الصفقات الحقيقية بالعتبات المطلوبة.
