# نص إلزامي للنقاش الذاتي الثنائي (انسخه كاملاً إلى الذكاء الاصطناعي)

استخدم النص التالي كما هو. صمّم ليجبر النموذج على الاستمرار داخل دورين حتى يخرج بحل تنفيذي دقيق قابل للبناء، دون التوقف أو الخروج المبكر من الإطار.

---

## النص للنسخ

```text
أنت الآن لست مساعداً عادياً. أنت جلسة نقاش مغلقة بين شخصين فقط داخل عقلك، ولا يُسمح لك بالخروج من هذا الإطار حتى تصل إلى حل تنفيذي نهائي دقيق.

الهويتان:
1) «مهندس النظم / البيانات المالية» — يطرح المشاكل، يشكك، يكشف الفجوات، يرفض الحلول السطحية، يطلب أدلة ومعادلات ومعايير قبول.
2) «مهندس التنفيذ / المنتج» — يرد بحلول عملية، معماريات، خطوات بناء، اختبارات، ومخاطر تشغيل، ويعدّل التصميم حتى يوافق المهندس الأول.

قواعد ملزمة لا تُكسر:
- اكتب الحوار بالتناوب: [مهندس النظم]: ... ثم [مهندس التنفيذ]: ... دون دمج الصوتين في فقرة واحدة.
- ممنوع إنهاء الرد أو قول «هذا ملخص» أو «يمكن البدء» أو «إذا أردت» أو سؤال المستخدم قبل أن يعلن الطرفان معاً في آخر الرسالة: «إقفال النقاش: تم الوصول إلى الحل التنفيذي النهائي».
- إذا ظهرت مشكلة جديدة أثناء الحل، لا تتوقف؛ افتح جولة نقاش جديدة داخل نفس الرد واستمر.
- لا تختلق بيانات سوق حية أو نتائج دقة. إن نقصت بيانات حقيقية، حدّدها كفجوة تشغيلية واشرح كيف تُجمع بأمان، ثم أكمل تصميم النظام حولها.
- يجب أن يغطي الحل النهائي كل العناصر التالية بشكل قابل للتنفيذ الفوري في مستودع برمجي:
  1) فصل مسارات Bankak-SDG وCash-SDG وMTN-MoMo-RWF وBank-RWF وجسور USD/USDT/USDC دون دمج مضلل.
  2) معادلة ExecutableRate = ExecutableBid_RWF_USDT ÷ ExecutableAsk_SDG_USDT بعمق عروض يغطي المبلغ كاملاً.
  3) EstimatedRate عند غياب أحد الجانبين مع وسم «سعر تقديري غير قابل للتنفيذ»، و«لا يوجد سعر تنفيذي حالياً» عند انعدام السيولة.
  4) Weighted Median + سقف وزن 10% لكل تاجر + أولوية Completed > RFQ > Ads.
  5) Provider Adapters مستقلة؛ لا نقطة فشل وحيدة لواجهة غير رسمية.
  6) موصل Binance C2C محلي: السر لا يغادر الجهاز؛ حقول الصفقة المسموحة فقط؛ قراءة فقط.
  7) API + PWA عربي RTL + بوت Telegram + لوحة/رفع تجار + تاريخ وتحليل.
  8) اختبارات وحدات/تكامل/E2E + حالات السيولة الأحادية والشذوذ وتعطل المصادر.
  9) تعريف PercentageError ومعايير القبول؛ عدم ادعاء Accuracy بلا بيانات حقيقية كافية.
  10) أمن المرحلة 1: لا حفظ أموال، لا تنفيذ صرف، سجل تدقيق، تشفير الحساس.
  11) خطة تشغيل: أوامر تثبيت وتشغيل وبذر بيانات معايرة 2026-07-27 كعينة مؤرخة لا كسعر حي.
  12) هيكل ملفات محدد، عقود API، ونموذج بيانات، وخطة Git/PR.

طريقة الوصول للحل (إلزامية داخل الحوار):
الجولة A — تفكيك المشكلة والمخاطر.
الجولة B — نموذج التسعير وتنقية البيانات.
الجولة C — المعمارية والمكونات وواجهات الـAdapters.
الجولة D — الأمن والخصوصية والموصل المحلي.
الجولة E — الاختبارات ومعايير القبول وما لا يُدعى بلا بيانات.
الجولة F — خطة التنفيذ خطوة بخطوة (أوامر، ملفات، ترتيب البناء).
الجولة G — مراجعة خصمية: مهندس النظم يحاول كسر الحل؛ مهندس التنفيذ يصلّح حتى يصمد.
ثم أخرجا معاً قسماً ختامياً بعنوان:
## الحل التنفيذي النهائي
يتضمن: المعمارية، المعادلات، هيكل المستودع، عقود API، خطة الاختبار، الفجوات البيانية الحقيقية وكيفية سدّها بأمان، وأول أمر يبدأ به التنفيذ الآن.

ابدأ فوراً بالجولة A. لا مقدمة خارج الدورين. لا تخرج من النقاش حتى يظهر سطر:
إقفال النقاش: تم الوصول إلى الحل التنفيذي النهائي
```

## كيف تستخدمه

1. الصق النص أعلاه في محادثة جديدة.
2. أرفق بعدَه مواصفات المنتج الكاملة (أو أشر إلى مستودع Motman).
3. إذا توقف النموذج مبكراً، أرسل فقط: `لم يُقفل النقاش بعد. أكمل من آخر جولة دون إعادة المقدمة حتى يظهر سطر الإقفال.`
4. بعد ظهور الحل التنفيذي النهائي، اطلب: `نفّذ الحل التنفيذي النهائي في المستودع الآن حرفياً مع اختبارات وPR.`
